### 2026-09-27 07:29:58 (0.1.0)

**Problem Description**

[version: minor]
Problem:
  On Linux, Aravis binds its GigE discovery UDP socket to each NIC's
  own IP address and broadcasts a discovery request to
  255.255.255.255. If no NIC on the host shares a subnet with the
  camera's IP (the common case when the camera's IP is unknown or in
  LLA/169.254.x.x), the broadcast never reaches the camera and the
  "Discover / Refresh" button in the Camera tab always reports
  0 cameras. Windows camera tools work because they bind the
  discovery socket to 0.0.0.0 instead.

Solution:
  Add an "Enable LLA (169.254.x.x)" button to the Network Card tab.
  When clicked, it runs:
      pkexec ip addr add 169.254.100.1/16 dev <iface>
  on the selected interface. Once the NIC also owns an address in
  169.254.0.0/16, the camera (which falls back to Link-Local when it
  cannot get DHCP / a persistent IP) becomes reachable via Aravis'
  normal broadcast mechanism, with no changes to Aravis sources and
  no changes to the existing Camera-tab code.

  This is the minimal-change variant:
    - No new source files are introduced.
    - CMakeLists.txt is not modified.
    - CameraConfigurator.cpp / CameraTab.* are left untouched.
